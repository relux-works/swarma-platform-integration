# Unresolved integration questions

All items below are execution or acceptance gates. A document, source commit, signature, delivery acknowledgement or successful render cannot close them.

| Boundary | Required input | Accountable role |
| --- | --- | --- |
| Launch authority | Published protected policy, exact caller-to-worker mapping, admitted operations/plans/profiles and prepare/effect currentness; independent review and owner approval | Dispatcher and operator |
| Owner activation | Published owner-root purpose, canonical body, exact references, verifier, replay retention and currentness at the consuming boundary; no invented signing template | Authority and Signer owners with broker and dispatcher |
| Station and caller | Qualified initial and boot tuple, active random-token generation, operator registration after durable activation, typed caller purpose and protected association | User-manager and Keymaker |
| Host dependencies | Operator-provisioned audit tools and executable-bound rule, initial/boot event delivery without loss/drift, reduced CapEff and nonempty receipted account inventory | Operator and independent qualifier |
| Bootstrap budgets | Accepted finite setup and dispatcher bounds, full workload limits and complete durable endpoints; proposed installation caps remain unadopted | All bootstrap consumers |
| Shared custody | Actual implemented serving and adapter frontier, separately enrolled histories/credentials, trusted time, fresh heads and independently enforced old-instance exclusion | Witness, Keymaker and broker owners |
| Broker | Complete native activation audit, runner and foreign-peer controls, time/store rollback closure, approved service topology and read-only worker status client | Broker and operator |
| Executor | Closed plan-to-runner entry, approved executable/handle, immutable input and native refusal before invocation | Dispatcher with launcher and broker owners |
| Result | Authenticated output channel, protected durable sink, capacity/overflow/retention rules, original outcome correlation and writer/reader/restore fences | Dispatcher and worker-runner owner |
| Stop and leases | Closed work/resumer inventory, quiet account-wide absence, independent release evidence and complete all-lease issuance horizon | User-manager, broker and independent qualifier |
| Security revocation | Automatic original-detection-to-final-material fence is absent; manual stop plus Replace leaves an uncovered detection-to-commit interval. Any limited canary needs explicit owner acceptance of that interval and every other gate | Security authority, broker and owner |
| Time | Native boot-inclusive elapsed continuity, trusted UTC/watermark, enforced post-read reserve and maximum-load completion measurements | Time provider and every consumer |
| Full authorization and result | Strict grant attenuation, broker binding, message signing/certification, unchanged Matrix delivery, replay state and independent verifier | Authority, broker, message and carrier owners |
| Registry and root currency | Witnessed snapshot publication, exact journal/fork/revocation checks, freshness use and agreed external-root currency format including grant and operator roots | Registry, format and Signer owners |
| Production custody and recovery | Independent provider/administration, archive/audit custody and surviving recovery evidence; no local reset fallback | Owner and custody operators |

Minimum kernel, systemd, auditd and tool versions and a complete dependency-specific refusal-code mapping are unknown here. Exact owning sources must establish supported versions; one observed environment never defines a range. Linux qualification does not qualify macOS. General session/workspace services, federation, pool and memory are outside the initial limited run; any actual selected dependency still needs its own accepted seam.
