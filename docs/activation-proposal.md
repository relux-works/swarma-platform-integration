# Inactive activation proposal

This is a requirements proposal. It grants no root, installation, live-account testing, signature, canary, activation or production permission. Document review, source landing, installed qualification and owner approval are distinct states.

Use existing broker qualification records, whole qualified-list identity, activation marker and phased cutover evidence. A marker binds its list; it is neither an owner grant nor proof of current installed identity. Every mandatory positive/negative row must actually execute and pass in the exact native tuple. Missing fences must be positively confirmed absent; unreadable fence state is unknown. A fake report, source hash, selected version string or partial record set cannot publish qualification.

Owner intent must bind the intended installation/receiver and personal root authority; exact source/binary/config/schema/policy/catalog/profile/adapter/qualification references; current OS/boot/service/caller/worker identities and generations; custody/time/exclusion; finite original validity, scope and count; revocation/replay/restore retention and one physical launch debit per original occurrence. No delegation, account creation, general deployment or automatic restart is inferred. Separately approved canary/load tests provide no count refill.

The owning authority and Signer services must publish the canonical purpose/body/verifier, pins, currentness and replay consuming paths. This document allocates none. Dispatcher or protected operator-installation verifies root signature, body, references and currentness. Launcher verifies its own receiver facts; Keymaker authenticates exact request bytes. Device act, registry-owner signer and station caller purpose are not interchangeable owner-root authority. Approval must precede canary; signature delivery is not execution acknowledgement.

The proposed service topology uses a dedicated broker daemon UID separate from worker/caller/dispatcher store and manager authority. Account-wide worker stop must not exempt a same-UID broker. A cooperative same-user standalone mode cannot satisfy this lifecycle boundary and is not a fallback when dedicated deployment is unqualified. Broker/vendor writers retain their own service fate/absence and trusted-writer limitations; worker absence says nothing about them. Actual multi-UID socket, server pin, runner/store/manager access and containment need native qualification. No UID number or provisioning command is selected here.

Ordinary setup keeps admission closed and proves zero leases broker-wide before policy replacement/reload and actual worker-status/foreign-UID controls. Emergency Replace has no zero-lease prerequisite and invalidates all old generations on success. Renewal preserves original authorized ceiling; failed old-generation release remains debt. Planned permission expiry closes new starts; security manual stop+Replace has the [uncovered interval](authority-lifecycle.md) and cannot be called qualified.

Cutover requires complete old launch/restart/watch inventory and confirmed writer/descendant absence before fresh-home owner enrollment. Keep old disk login inert; do not copy/adopt it. With ordinary admission closed, obtain approved live qualification, exact publication/reread, verified owner intent, separately authorized canary/load, and safe old-login retirement LAST. If selective vendor retirement is unproved, retirement remains pending; no blind vendor-wide logout or automatic rollback.

Existing cooperative stores require a separately reviewed/tested migration path: maintenance exclusion, exact old-manager inventory/closure and retained unknown outcomes, trusted same-filesystem offline move with destination absence and preserved records, guarded ownership, approved new identities/keys, old-lease invalidation, new containment/readiness/qualification and explicit approval. A new empty manager cannot establish old writer absence. No silent copy/delete, reconstructed missing store, adoption of authority, automatic reopen or assumption of initial fresh deployment bypasses migration. Failed/unknown recovery keeps both admissions closed and preserves resources.
