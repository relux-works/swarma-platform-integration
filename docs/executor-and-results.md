# Executor and result boundaries

Dispatcher owns the versioned closed plan decoder, exact executor entry, bounded output capture, original outcome and evidence retention. User-manager owns approved executable admission, pre-run digest-pinned skeleton home, bounded cwd, immutable read-only FD3, launcher/observe/stop and receiver commit interlock. Broker owns the contained worker runner, lease/credential/private-harness lifecycle and final assistant artifact; it does not decode FD3.

The admitted decoded plan is at most 48 KiB and the whole launch request at most 80 KiB. A larger broker prompt ceiling does not widen either. Operator installs an approved absolute executor path with exact digest, no symlink following and a retained verified executable handle. Daemons do not install arbitrary executors. No inherited service or broker descriptor may enter the worker.

The selected `run-codex` subset binds account, profile, launch home, model, reasoning effort and last-message output; prompt enters only through prompt stdin. Only the separately admitted cwd/timeout options may vary. No shell, arbitrary executable, extra flags, credential-bearing variables/options, home prompt-file fallback or implicit resume. Preserve the owning runner's exit meanings and original deadlines; this document supplies no new command implementation.

Malformed/oversize plan, unapproved path, digest mismatch or forbidden argv/FD must refuse before runner/harness invocation. That refusal does not prove no preparatory process or committed attempt: retain root receipt, spent start debit, uncertain effects and cleanup debt. A start receipt or turn-start is insufficient; a successful limited run needs one COMPLETED real approved turn with bounded final result correlated to the original effect.

Results require an authenticated producer-to-dispatcher channel and protected bounded durable sink, binding original effect, worker generation, plan/profile/policy and input. Retain final text, bounded stream, sanitized diagnostics and required audit/custody/recovery evidence. Reserve capacity before admitting work; publish byte/state/overflow/retention/export limits and final-writer/reader/restore fences. A worker-only file mode does not grant dispatcher read authority. Nonterminal deltas, a final file or exit alone do not prove whole-account absence, successful release or token expiry.

Lost/unauthenticated output, overflow, capacity/retention failure, failed/interrupted turn, unknown teardown or failed release yields no clean success. Each independent debt survives. General workspace/archive import, arbitrary home copy and full session services are outside this bounded immutable-input/text-output selection; necessary output export and evidence retention remain included and open. Actual entry/result joins and native enforcement must be published and qualified.
