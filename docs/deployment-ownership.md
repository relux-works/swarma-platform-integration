# Deployment and authority ownership

Roles identify responsibilities and required approvals, not people, machines or deployed placement. Assignment, delivery, receipt, content approval, source publication, native qualification and activation are separate facts.

| Role | Authority and required boundary |
| --- | --- |
| Integration coordinator | Correlates exact evidence, dependencies and unresolved joins; holds no service, root or owner authority |
| Independent qualifier | Defines real-boundary positive, refusal, narrowing and unknown controls; evaluates exact exported evidence independently. Synthetic fixtures are not native qualification; conflicts must be disclosed |
| Operator | Installs only owner-approved releases/keys/channels, audit rules and service topology in approved maintenance; keeps exact inventory, rollback target and real child exits. Daemons receive no root authority |
| Personal owner root | Retains personal/offline/device custody and decides explicit risk, canary and production scope. Never relocated to the online trust service |
| Registry and isolated registry-owner signer | Separate storage/order from signer key, accounts/processes/streams and transport/pins; signer verifies intended exact content, not writer-provided validity flags |
| Witness and custodian operators | Separate administration/keys/recovery; synchronous exact predecessor and fresh heads; independent old-instance enforcement and separate consumer histories |
| Dispatcher | Protected local policy/root-record verification, caller association, intent/claim/effect/reconciliation, closed executor entry, bounded output/outcome/export/retention and independent deadline stop |
| User-manager and launcher | Qualified station identity/generation, creating-dispatcher ownership, approved skeleton/FD3/handle, receiver interlock, observe/stop and closed account-wide quiet absence; no root-record verifier role |
| Keymaker | Qualified station caller authentication, typed purpose separation, association/currentness, retained owning-store result/audit/use fences; no launch-policy authority |
| Broker and worker runner | Protected credential policy, own current checks, worker-owned lease I/O and original ceiling, independent store/time custody, contained vendor writer and separate material/release/token dispositions |
| Carrier, registrar and result verifier | Actual signed-byte transport/intake/replay, independently current authorization and isolated carrier admission qualification where selected; sender identity alone is insufficient |

Before install, publish exact immutable release/config/pin identities, ownership/permissions, compatible retained state, protected observation/recovery, account/network denial, trusted time and finite budgets. Maintenance fences every activation/resumer path, retains affected-set/unknown obligations and confirms complete quiet absence before swaps. Recovery never silently resets history or changes mode.

Linux may proceed only after its exact native tuple is qualified and separately activated. macOS remains closed until its own native qualification; Linux evidence supplies no parity credit. Production custody needs independent provider and requalification. Source/render evidence establishes none of these deployment facts.
