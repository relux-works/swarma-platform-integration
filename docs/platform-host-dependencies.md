# Platform host dependencies

Linux user-manager qualification requires operator-provisioned dependencies. On Ubuntu, use `auditd` from the standard Ubuntu repository, protected `auditctl` and `ausearch`, enabled auditing and a live working Audit daemon. The user-manager daemon does not install packages, start/configure Audit or load its own rules. Package presence alone qualifies nothing. See the exact [owning README](https://github.com/relux-works/swarma-user-manager/blob/e1719ea6aa42c2af601b6153c3da53c6bcfd3802/README.md) and [backend Audit limits](https://github.com/relux-works/swarma-user-manager/blob/e1719ea6aa42c2af601b6153c3da53c6bcfd3802/docs/linux-backend.md#d1-audit-and-qualification-limits).

The executable-bound audit rule is protected operator configuration. Rebind it whenever an approved upgrade replaces the executable. Qualification must establish the exact installed and loaded rule and fresh matching successful socket events for BOTH initial and boot qualifier processes, with no intervening audit loss or boot drift. Audit records attempts/results; it is not payload or inventory-completeness authority.

The native socket filter permits AF_UNIX and the exact AF_NETLINK / SOCK_RAW|SOCK_CLOEXEC / NETLINK_SOCK_DIAG socket triple, synchronized across threads; AF_NETLINK socketpair and other new network sockets refuse. Unsupported ABIs refuse. See the exact [network source](https://github.com/relux-works/swarma-user-manager/blob/e1719ea6aa42c2af601b6153c3da53c6bcfd3802/internal/linuxos/network_linux.go). Actual issuer CapEff must exclude CAP_NET_ADMIN; actual thread capabilities must be consistent and readable, rather than inferred from unit configuration. See [capability measurement source](https://github.com/relux-works/swarma-user-manager/blob/e1719ea6aa42c2af601b6153c3da53c6bcfd3802/internal/linuxos/capabilities_linux.go).

Both qualification flows require complete inventory of NONEMPTY receipted reserved accounts. Empty account sets, a unit file, one reported qualification record or an unprivileged fixture do not establish native initial/boot qualification. An incomplete reduced-capability dump remains unknown with admission closed; never restore CAP_NET_ADMIN, use a helper or substitute a proc-only clean result. Foreign or unreadable namespaces refuse.

The [backend documentation](https://github.com/relux-works/swarma-user-manager/blob/e1719ea6aa42c2af601b6153c3da53c6bcfd3802/docs/linux-backend.md) also requires exact protected policy/input pins, full account-directory scope and successful current-boot renewal binding. Changed binary/configuration/boot/profile requires the owning requalification path. This page establishes no installed package, loaded rule, audit delivery, boot receipt, current native architecture or qualified host.

Supported minimum versions of kernel, systemd, auditd and tools and a complete dependency-to-refusal-code mapping are unknown here. No version range is inferred from a source test, CI image or one observed machine. Obtain the exact owning compatibility/refusal contract before installation. Linux requirements do not qualify macOS or authorize privileged execution.
