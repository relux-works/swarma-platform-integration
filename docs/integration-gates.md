# Integration qualification gates

These are documentary acceptance obligations, not existing test functions or passing runtime evidence. Qualification uses real owning entry points, exact installed source/binary/build/config/schema/policy/OS/kernel/boot/UID/generation/profile/association/time/custody identity, original request and deadlines, protected raw receipts and independent post-state observation. Each negative needs a nearby valid control in the same tuple. Missing production entry points stay pending; helper fixtures cannot qualify them.

## Lease and absence distinctions

Normal release needs independent native evidence at the actual owning worker/broker boundary; EOF, status or output is insufficient. A killed runner can reach qualified lease expiry only with complete issuance horizon and account absence; it never implies release. A different admitted worker's release must return the owning protocol's not-owner refusal with lease/renewal/owner state unchanged except permitted telemetry. Dispatcher remains unlisted and gains no foreign receipt.

Selected expiry disposition uses protected actual policy/version maxima, original occurrence, qualified time and a CLOSED issuance interval covering EVERY possible lease, in-flight work and prevention of later issuance, including after receiver absence. A conservative horizon H >= max over versions (latest possible issuance + that version's maximum) is valid only with qualified complete coverage and time. Missing/forged/partial/unreadable/cross-occurrence evidence retains debt while stop progresses. First-start plus one guessed maximum, current policy only, one lease or account absence is insufficient. No observer or new handoff API is invented. Lease/token/output/custody/stop dispositions remain independent.

Closed whole-account absence must cover or prohibit namespaces, credential transitions, schedulers/activation paths, escaped/pre-receipt descendants, same-UID resumers and delegated work outside the sampled UID. Maintain fences through quiet and until authorized reopening. Empty cgroup, leader exit, one UID sample or quiet alone is insufficient. Read failure is unknown, never absence.

## Later full acceptance

The fifteen required areas are: qualified station/drift refusal; typed caller-purpose/current generation; strictly attenuated delegation; dispatcher single-effect/replay; credential lease/current renewal; signed message/attestation and unchanged Matrix result; complete registry snapshot/journal/fork/revocation review; original-expiry process-local freshness receipt use; agreed external-root currency covering grant AND operator roots; exact predecessor custody; old writer/signer/use exclusion; surviving-evidence recovery; original-detection security fencing and <=300s affected-work response; status/observe/reconcile/authorized stop progress under holds; and whole caller budget across all pages/transport/durability/use.

For snapshot review, reject stale/future snapshots, equal-sequence differing checkpoints, rollback/forks/gaps, incomplete cumulative revocations and foreign authority without advancing anchors/effects. For signed result, reject wrong purpose, root, chain, domain, receiver, body or replay without authorized action. Attenuation must narrow action/account/profile/window/depth; a credential leaf is not caller authority. Full revocation completion needs durable barriers/acknowledgements or proven expiry of all prior authority plus a current critical-effect check. Snapshot publication timing bounds neither malicious withholding before publication nor the separate detection response. Existing root own-age checks remain until the accepted currency delta, without fallback.

Runtime evidence credited here: **0/15 areas; 0 runtime mutants killed**. No live deployment, privacy-proof, qualification or publication conclusion follows from a documentary gate.
